# Collaborators V1 API contract

All paths are under `/api`; authenticated routes use the existing session/Bearer login. Amounts and percentage are decimal **strings**, never floating-point JSON numbers. All calendar months use `America/Argentina/Buenos_Aires`. Errors return `{ "error": "message" }`.

Consent endpoints and policy: see `docs/legal-consent-v1.md`. `GET /consents/status` reports the authenticated user's own current-version status. `POST /consents/accept` accepts `{types:["terms","privacy"]}` or `{types:["ai"]}`; the server derives both user IDs and timestamp, and never accepts an identity from the request. IA endpoints return `428 {code:"AI_CONSENT_REQUIRED", consentType:"ai", version}` before processing when the current notice has not been accepted.

* `GET /referrals/:code` public: `{ "valid": boolean, "code": "NORMALIZEDCODE" }`. Invalid/inactive codes return `valid:false`; no account data is exposed. Codes are uppercase ASCII letters/digits (2–32). Browser must save first *valid* code in first-party storage for 30 days and pass it in registration; server revalidates.
* `POST /auth/register` existing professional body plus optional `"referralCode":"CODE"`; creates permanent attribution atomically with account, storing `codeUsed`, source `public_register`, and no actor. Invalid/inactive code returns 400; existing user still returns 409. Admin `POST /users` with professional role also accepts `referralCode` (source `admin_user_create`, actor authenticated admin). Neither account endpoint returns referral identity.
* `GET /collaborators` admin: array of `{id,userId,name,country,code,commissionPercent,active,createdAt}`.
* `POST /collaborators` admin: `{name,email,password,country,code,commissionPercent}` creates an *inactive* collaborator and associated collaborator-role login atomically; alternatively `{name,existingUserId,country,code,commissionPercent}` links an existing professional, creating only the collaborator row. The modes are exclusive: existingUserId cannot be combined with email/password. Linking never changes the user's role, password, active state or clinical data. Returns same shape with `active:false`. Enable explicitly after security verification using PATCH. Invalid mode returns 400, missing/non-professional user 404, duplicate user/code/email 409.
* `PATCH /collaborators/:id` admin: subset of `{name,country,code,commissionPercent,active}`; code immutable after attribution or receipts. Returns collaborator shape. Name/active changes synchronize only dedicated collaborator-role logins, never linked professional accounts.
* `GET /collaborators/:id/dashboard` admin and `GET /collaborator/dashboard` collaborator: `{name,code,link,commissionPercent,referrals,activeSubscriptions,newSubscriptionsThisMonth,cancellationsThisMonth,generatedThisMonth,pending,paid,history}`; money maps keyed by ISO currency to decimal strings, e.g. `{"ARS":"100.00"}`. `history` is array `{month,referrals,newSubscriptions,cancellations,generated,pending,paid}` (same currency maps). No referred account identifiers or contact details.
* `GET /saas/receipts` admin: array `{id,professionalUserId,amount,currency,periodFrom,periodTo,receivedAt,reference,idempotencyKey,createdByUserId,collaboratorId,commissionPercentSnapshot,commissionAmount,paidAt,paidByUserId,paymentReference,createdAt}` (snapshot/commission/payment nullable without attribution).
* `POST /saas/receipts` admin: `{professionalUserId,amount:"100.00",currency:"ARS",periodFrom:"2026-01-01",periodTo:"2026-01-31",receivedAt:"2026-02-02",reference?:"transfer-id",idempotencyKey:"unique-operation-key"}`; period dates **required** and ordered. `201` receipt. Repeated identical payload/key returns existing receipt `200`, mismatched payload/key `409`. Confirmed receipt immutable. Server stores `createdByUserId` from session, never accepts it from client. Only full commission can be paid.
* `POST /saas/receipts/:id/paid` admin: `{paymentReference?:"transfer-id"}` marks full commission paid and records `paidByUserId` from session, returns receipt; identical repeat is idempotent, different reference after payment returns 409. Receipt without commission returns 409.
* `POST /saas/status` admin: `{professionalUserId,status:"paying"|"churned"|"trial"|"overdue"|"courtesy",effectiveDate?:"2026-02-02"}`; returns `{professionalUserId,status,event}` where event is `"first_paid"|"cancellation"|"reactivation"|null`. Actor always derived from authenticated admin. Existing admin `PATCH /users/:id` commercialStatus uses same transition logic. Older paid/overdue/churned subscriptions receive a non-counted `baseline` event, never incorrectly counted as a new first paid signup.

For collaborators the global auth barrier allows only exact `GET /auth/me`, `POST /auth/logout`, `GET /collaborator/dashboard` after database-backed identity validation. Every other `/api` route returns 403. Anonymous public registration/referral validation remain separate.

Professionals retain their existing role permissions. `GET /collaborator/dashboard` additionally allows a professional only when a collaborators row belongs to the authenticated user; it returns 403 without membership. Dashboard ownership never comes from a supplied collaborator ID.
