CONTEXTO

Actualmente, cuando desde administración se elimina un usuario,
aparentemente el sistema no lo elimina realmente sino que establece:

active = false

Además, los pacientes y otros datos relacionados con ese profesional
permanecen guardados.

Quiero corregir esto, pero ANTES necesito conocer todas las relaciones
para evitar pérdida accidental de información clínica.

AUDITAR:

"Eliminar usuario".

Identificar:
- componente/botón frontend;
- endpoint utilizado;
- lógica backend;
- cambios realizados en la tabla users;
- si existe eliminación física o solamente active=false.

2. Identificar TODAS las tablas y registros que pueden estar relacionados

- objetivos

- agenda/citas
- archivos

- actividades
- cualquier otra tabla que tenga:
  user_id

  owner_id
  o cualquier relación equivalente.

3. Determinar qué ocurre actualmente con los PACIENTES cuando el profesional

¿Siguen visibles?
¿Para quién?
¿Quedan asociados al profesional desactivado?
¿Puede otro profesional acceder a ellos?
¿Puede el administrador reasignarlos?

4. Determinar qué ocurriría si se intentara eliminar físicamente un usuario.

Identificar:

- restricciones;
- tablas que impedirían el borrado;
- información que se eliminaría automáticamente.

NO realizar el borrado. Solo analizarlo.

5. Diferenciar conceptualmente estas acciones:

A) DESACTIVAR USUARIO
La persona deja de poder ingresar pero se conserva toda su información.

B) ELIMINAR CUENTA
Se elimina la cuenta de acceso, pero debe definirse qué ocurre con la
información clínica relacionada.

C) ELIMINAR DATOS
Eliminación definitiva de información asociada, únicamente cuando
corresponda y mediante una acción explícita.

Analizar si la arquitectura actual permite separar correctamente
estas tres acciones.

6. Diseñar una opción segura para administración que permita:

DESACTIVAR
→ conserva cuenta y datos
→ impide acceso.

ELIMINAR CUENTA
→ requiere confirmación fuerte
→ muestra antes qué información está relacionada
→ permite resolver los pacientes asociados.

Antes de eliminar una cuenta con pacientes asociados debería poder elegirse,
según lo que permita la arquitectura:

- reasignar pacientes a otro profesional;
- dejar pacientes sin profesional;
- cancelar la eliminación.

NO asumir que eliminar un profesional implica eliminar sus pacientes.
